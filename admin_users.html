FRP 公网登录 / VPN 验证

该地址既可用于普通 OHA 公网登录，也作为 VPN 专用控制通道。VPN 弹窗用户验证、单用户权限检查、SSTP 参数读取和 SSTP 公钥证书下载均只通过此 FRP 公网 HTTPS 地址完成，不再回退内网 OHA Server。首次院外冷启动仍需在 client-config.json 预置该地址，或本机此前已缓存过该公网地址。

FRP HTTPS 证书验证

默认应保持严格验证。仅当 FRP 公网地址使用自签名、名称不匹配或暂未受系统信任的 HTTPS 证书时，为兼容测试可开启。开启后只放宽 OHA 客户端访问 FRP 公网控制面的证书验证；不会关闭 Windows SSTP/Schannel 的服务器证书校验，也不会影响 HIS 或 DeepSeek 网页版。该模式会降低公网身份验证的抗中间人攻击能力。

DeepSeek 网页版外部跳转

只限制 DeepSeek 网页版的顶级页面跳转与新窗口，不拦截页面正常加载的 CDN、脚本、字体等子资源。医院部署建议保持开启并选择“阻止外部网站”。

DeepSeek 允许域名

每行一个根域名；填写 deepseek.com 会同时允许 chat.deepseek.com 等子域。当前 DeepSeek 首页自身的域名始终自动允许。

扩展网页管理

每条书签填写名称和完整网址。客户端“扩展”会在与主 HIS 相同的 WebView2 环境中新开窗口；仅允许在所配置书签域名内浏览，服务端模块仍按各自匹配规则注入。勾选时窗口顶部显示完整网址（包含 http:// 或 https://、端口、路径及参数）；取消勾选时隐藏地址。

DeepSeek 网页版书签管理

书签在 DeepSeek 独立窗口打开。请另外把对应域名加入上方“DeepSeek 允许域名”，否则仍会被跳转限制阻止。

远程接入按钮总开关

关闭：客户端登录前不显示 VPN/代理按钮。开启：客户端在未登录阶段即可显示按钮；点击后通过弹窗输入 OHA 用户名和密码，并仅通过“允许公网域名登录验证”配置的 FRP HTTPS 地址验证，再检查该用户是否拥有“VPN/远程接入”权限。

远程接入模式

SSTP 使用 Windows 原生 RAS；HTTP代理只作用于主 HIS WebView2，不创建额外虚拟网卡，也不会影响 DeepSeek 网页版。

SSTP 连接名称

写入 Windows RAS 电话簿的连接名称。客户端不会显示该配置值。

SSTP 服务器

只填写 VPN 服务器的域名或 IP，不要填写 https:// 或路径。SSTP 使用服务器证书，Windows 必须能够正常信任该证书。

SSTP 信任证书

用于客户端信任 SSTP 服务器证书或其签发 CA。只上传 .cer / .crt / .der 公钥证书；不要上传 .key 私钥。客户端只通过 FRP 公网域名下载证书，并通过 Windows certutil + UAC 安装到“本地计算机\\受信任的根证书颁发机构”。OHA 不再因为 CN/SAN 与 VPN 地址不同而阻止配置；但 Windows 原生 SSTP/Schannel 仍可能执行系统级名称校验。

VPN 登录密码

HIS HTTP 代理地址

格式 http://host:port。仅主 HIS WebView2 使用；OHA API 的 HttpClient 和独立 DeepSeek WebView2 都不使用此代理。

接入路由模式

SSTP：分流时关闭 Windows“在远程网络上使用默认网关”，VPN IPv4 保持“自动跃点”，并通过一次 UAC 添加下方非持久路由，下一跳固定 192.168.30.1；正常断开后路由随 PPP 接口失效。全局时删除 OHA 分流路由、保持“自动跃点”并启用 Windows VPN 默认 IPv4 路由；客户端会在拨号前为实际 SSTP 公网端点添加一条经原物理网关的 /32 保护路由，避免默认路由回卷造成 VPN 自动掉线。全局模式下的公网访问仍要求 VPN 服务端提供可用的转发/NAT 和 DNS；如果服务端只提供医院内网，请使用分流模式。HTTP代理：分流时 PAC 仅对下方网段返回代理，其它页面 DIRECT；全局时主 HIS WebView2 的全部页面请求走该 HTTP 代理。

指定接入网段

仅在“仅指定网段”模式使用，每行一个 IPv4 CIDR，例如 11.12.199.0/24。SSTP 模式用于 Windows 路由；HTTP代理模式用于 WebView2 PAC 匹配。
